## 2. Architecture today

```
Browser (GitHub Pages)  --POST JSON-->  Supabase Edge Function "swift-task"  --service role-->  Postgres
  index.html / script.js                (index.ts: start | guess | hint)                          daily_puzzle
  session id in localStorage                                                                       game_sessions
  Google Analytics (gtag)
```

- The browser only holds the **public** Supabase URL and publishable key (`script.js` lines 8-10). That is by design.
- The **service-role key** exists only as a function environment variable (`SUPABASE_SERVICE_ROLE_KEY`, `index.ts` line 57). No key value is stored in this repository.
- The browser never reads or writes tables directly. All game logic runs in the function.

## 4. Security posture (verified 2026-10-17)

- RLS is **enabled** on `game_sessions`, `leaderboard`, `puzzles` and `daily_puzzle`.
- `game_sessions`, `daily_puzzle` and `puzzles`: no policies, and no grants to `anon` or `authenticated`. Only the service role (the function) can use them.
- `leaderboard`: grants `INSERT` and `SELECT` to `anon`, with two policies:
  - "Anyone can submit a score" (INSERT): nickname length 1-16, score 0-50, elapsed_seconds 1-3600.
  - "Anyone can view leaderboard" (SELECT): `true`.
- The function restricts browser origins to `https://prajaktao.github.io` (`index.ts` line 5). CORS is not an access control; non-browser clients can still call the function.

## 5. Edge Function contract (`swift-task`)

All requests are `POST` with a JSON body containing `action` and `sessionId` (a UUID, format-checked). `OPTIONS` returns 200 with the CORS headers. Other methods return 405.

"Today" is the **Asia/Kolkata** calendar date (`getTodayIndia`, line 20), so the puzzle changes at midnight IST.

| Action | Extra input | Behaviour | Success response |
|---|---|---|---|
| `start` | none | Creates the session for today's active puzzle if none exists. If a session exists for another day, returns 409. | Snapshot |
| `guess` | `answer` (non-empty string) | Normalises and compares the answer. Attempt `n+1`. The session completes on a correct answer or after the **3rd** attempt. | Snapshot + `correct`, `message` |
| `hint` | none | Returns the next hint from `hints[hint_index]` and advances the index. Hints do **not** use attempts. | Snapshot + `hint` (string, or `null` with a "No more hints" message) |

**Snapshot fields:** `puzzleDate`, `category`, `question`, `attempts`, `hintsUsed`, `completed`, `solved`, `elapsedSeconds`. When the session is completed, `answer` and `explanation` are added. They are never sent before completion.

If a session is already completed, `guess` and `hint` return the completed snapshot with the answer and explanation.

**Errors:**

| Status | When |
|---|---|
| 400 | Invalid session id, empty answer, or unknown action |
| 404 | `guess` or `hint` for a missing session or one from another day |
| 405 | Method is not POST |
| 409 | `start` with a session from another day (the browser then creates a new session id) |
| 500 | Server configuration problem or unexpected error |
| 503 | No active puzzle scheduled for today |

**Answer normalisation** (lines 17-18): lowercase, Unicode NFKC, then remove every character that is not `a-z` or `0-9`. Both the guess and each accepted answer go through it.

**Elapsed time** (lines 29-41): `completed_at` (or now) minus `started_at`. It runs while the page is closed.

## 6. Verified findings (each becomes a Version 2.0 requirement)

| ID | Finding | Evidence | Impact |
|---|---|---|---|
| F1 | Attempt counting is read-then-write: `nextAttempts = session.attempts + 1` (line 268) is computed from an earlier read, and the update only checks `completed = false` (lines 271-284). Parallel guesses can all read the same count, so the limit of three can be exceeded. The same pattern affects `hint_index` (line 228). | Code review. **Not yet reproduced by a test.** | Bypass of the 3-attempt rule |
| F2 | The session id is generated by the browser and a new one is created when the stored one is from another day. A script can create unlimited sessions per day. The function has no rate limiting. | `script.js` lines 227-262, `index.ts` | Extra attempts; blocks any trustworthy leaderboard |
| F3 | The normaliser strips all non-`a-z0-9` characters, so symbol-only or non-English answers can normalise to an empty string and clash. "1/2" and "12" become identical. | `index.ts` lines 17-18 | Wrong answers accepted for some future puzzles |
| F4 | Revealed hints are not returned in the snapshot, so a page refresh loses hints already shown. | `index.ts` lines 121-150 | Poor experience |
| F5 | CORS allows only the GitHub Pages origin. | `index.ts` line 5 | Blocks local, staging and Cloudflare Pages testing |
| F6 | A missing puzzle returns 503 (lines 165-168). A session that spans midnight gets 404 on `guess`/`hint` (lines 196-199). The frontend shows developer-oriented text. | `index.ts`, `script.js` line 256 | Confusing failures |
| F7 | `leaderboard` lets anyone with the public key insert rows directly (nickname 1-16 chars, score 0-50, time 1-3600 s) and read all rows. The deployed game does not use it. | Audit policies and grants | Fake scores possible if the table is reused. Decide whether to drop or lock it down at cutover. |
| F8 | There is no persistent player identifier, no foreign key from `game_sessions` to `daily_puzzle`, and no index on `game_sessions.puzzle_date`. | Audit constraints and indexes | Blocks streaks and per-day queries |

## 7. What must not change yet

The live site (GitHub Pages, `main` branch, the production Supabase project, and the function named `swift-task`) must keep working until the planned switch. Rules for later steps:

- Develop on `v2-development` and in a separate staging Supabase project.
- Deploy new backend code under a **new function name**; leave `swift-task` alone until cutover.
- Production database changes must be **additive** (new tables and columns only) and reviewed before they are run.
- Never put a service-role key or database password in this repository.

## 8. Follow-up: capture the remaining unknowns (read-only)

Run this in the Supabase SQL Editor of the **production** project. It only reads. It returns column definitions, counts and names, not data rows.

```sql
select json_build_object(
  'columns', (select json_agg(json_build_object('table', table_name, 'column', column_name, 'type', data_type, 'nullable', is_nullable, 'default', column_default) order by table_name, ordinal_position) from information_schema.columns where table_schema = 'public' and table_name in ('leaderboard','puzzles')),
  'constraints', (select json_agg(json_build_object('table', conrelid::regclass::text, 'name', conname, 'definition', pg_get_constraintdef(oid))) from pg_constraint where conrelid in ('public.leaderboard'::regclass, 'public.puzzles'::regclass)),
  'indexes', (select json_agg(json_build_object('table', tablename, 'name', indexname, 'definition', indexdef)) from pg_indexes where schemaname = 'public' and tablename in ('leaderboard','puzzles')),
  'triggers', (select json_agg(json_build_object('table', event_object_table, 'name', trigger_name, 'event', event_manipulation)) from information_schema.triggers where trigger_schema = 'public'),
  'sql_functions', (select json_agg(json_build_object('name', routine_name, 'type', routine_type)) from information_schema.routines where routine_schema = 'public'),
  'extensions', (select json_agg(extname) from pg_extension),
  'leaderboard_rows', (select count(*) from public.leaderboard),
  'puzzles_rows', (select count(*) from public.puzzles)
) as audit2;
```

Also check in the dashboard: **Edge Functions** (the list of functions, and the JWT verification setting for `swift-task`) and **GitHub, Settings, Pages** (source branch and custom domain).
